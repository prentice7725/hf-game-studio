# 밸런스 점검

Claude-Code-Game-Studios의 `balance-check` 스킬을 hf-game-studio용으로 줄인 것이다(MIT, NOTICE.md 참고).
읽기 전용이다. 데이터를 고치지 않고, 고칠 일이 있으면 balance-data 작업(task.mjs)으로 넘긴다.

## 문서 읽기

설계 문서는 통째로 읽지 않는다. 먼저 `grep -n '^#' <문서>`로 제목과 줄 번호를 보고, 필요한 섹션의 줄 범위만 Read의 offset/limit으로 읽는다. 문서가 커질수록 통째 읽기는 토큰을 크게 쓰고, Read 한도(약 2.5만 토큰)를 넘으면 실패한다(원본 템플릿 이슈 #64, #136).
이 점검에 필요한 섹션은 보통 `design/gdd.md`의 "수치와 공식"과 대상 규칙 섹션이다.

## 0. 입력부터 확인

필요한 입력(데이터 파일, GDD 수치 섹션, 스키마)을 하나씩 `있음`/`없음`으로 적는다.
없는 입력이 필요한 항목은 **`평가 불가 - 데이터 없음`**으로 둔다. 추정으로 채우지 않는다.
데이터가 전혀 없으면 보고서 전체를 `평가 불가`로 끝낸다. 이것도 정상적인 결과다.

## 1. 영역 정하기

인자에서 영역을 정한다. 파일 경로면 내용으로 판단한다.
- 전투·계약 해결: 성공 확률, 능력치 대비 난이도
- 경제: 획득(faucet)·소모(sink), 가격, 세션당 순증감
- 성장: 레벨·능력치 곡선, 정체 구간, 급상승 구간

## 2. 점검

`design/gdd.md`의 "수치와 공식" 표에서 공식을 찾아 실제 데이터로 계산한다. 계산은 Bash의 `node -e`로 해도 된다.
- **극단값:** 최소·최대 능력치로 가장 쉬운·어려운 계약을 풀었을 때 확률이 0% 또는 100%가 되는가? GDD가 의도한 것이 아니면 지적한다.
- **지배 전략:** 다른 선택을 무의미하게 만드는 용병·계약·아이템이 있는가? (같은 비용에 모든 능력치가 높음 등)
- **자원 흐름:** 자원마다 획득처와 소모처가 모두 있는가? 한 세션 기준 순증감은?
- **공식 밖 숫자:** 공식으로 설명되지 않는 값(매직 넘버)이 있는가?
