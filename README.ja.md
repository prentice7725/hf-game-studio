# hf-game-studio

[한국어](README.md) · [English](README.en.md)

**Claude Code でゲームを作るためのスキルです。** 企画とコードは Claude が自分で担当し、ほかの AI は得意な仕事にだけ呼びます。

| 仕事 | 担当 |
|---|---|
| 企画、コード、数値、検収 | Claude |
| シナリオ、セリフ | Gemini (Argon) |
| 画像、効果音 | [asset-pipeline](https://github.com/prentice7725/asset-pipeline)(ComfyUI など) |
| コードレビュー | 別の会社のモデル(既定は Codex) |

ほかの AI はファイルを書き換えられず、結果を返すだけです。画像と音は、人が見て聞いてから採用します。

## なぜ使うのか

AI にゲームを任せると、よく二つのことが崩れます。

1. **「できました」が信用できない。** そこで作業ごとに**機械が実行するチェック**を先に決め、それが通って初めて完了とみなします。
2. **作ってから面白くないと気づく。** そこで大きなものを作る前に、**小さな実験**で「この選択は本当に結果を変えるのか」を確かめます(v3、試行中)。

## インストール

必要なもの: Node.js 24 以上、Git、Claude Code。ほかの AI は使うものだけ入れれば十分です(`codex`、`agy`、asset-pipeline)。

```bash
git clone https://github.com/prentice7725/hf-game-studio.git ~/.claude/skills/hf-game-studio
```

ゲームのリポジトリに入れる:

```bash
node ~/.claude/skills/hf-game-studio/scripts/setup.mjs <ゲームのリポジトリ>
```

設計ドキュメントのひな形(`design/`)、チェックツール(`tools/hfgs/`)、補助スキル(`.claude/skills/gs-*`)が入ります。既存のファイルは上書きしません。

- Web プロトタイプ(Phaser 4)も入れるなら `--phaser`
- Godot 4.7 の本編も入れるなら `--godot`

## 使い方

ゲームのリポジトリで Claude Code を開き、言葉で頼むだけです。例:

- 「傭兵データの最初の項目を作って」
- 「依頼掲示板の画面をプロトタイプで作って」
- 「主人公の肖像画の候補を3枚出して」

Claude は次の順序を自分で踏みます。

```text
作業の定義 → チェックがまず失敗することを確認 → 実装 → チェックが通ることを確認 → 別の AI がレビュー →(画像・音は)人が承認
```

### 実験(v3、試行中)

| スキル | すること |
|---|---|
| `/gs-inspect` | 設計ドキュメントとコードを突き合わせ、食い違いと次に確かめる問いを出す |
| `/gs-research` | 似たゲームがその問題をどう解いたかを出典付きで調べる |
| `/gs-experiment` | 一つの問いを実験カードにする: 仮説、間違いとみなす条件、測定を作る前に書く |

実験は安いものから行います。シミュレーションで答えが出れば画面は作りません。

```text
シミュレーション → Web プロトタイプ → Godot 本編
```

## 守られるルール

- **チェックはまず失敗しなければなりません。** 手を入れる前から通るチェックは何も確かめないので受け付けません。
- **チェックの基準は変えられません。** 作業中にスキーマ、アセット規格、用語集を変えると失敗します。
- **決めた範囲の外のファイルを変えると失敗します。**
- **レビュアーは作者の説明を受け取りません。** 変わったコードとチェック結果だけで判定します。
- **実験のしきい値は作る前に書き、結果を見てから変えません。**
